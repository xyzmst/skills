# 设计稿 → XML

照 Figma / 截图写布局 XML 时读。顺序固定：**参考图 → 分块 → 尺寸语义 → 资产清单 → 按块交付**。前三步只看设计稿几何关系和截图，不等切图。

适用范围：新写或大改一块布局。单点调整（改对齐、换一张图、调一个间距）直接改，不出分块表。分块表在 B 档就是决策表；在 C 档随该片的文件白名单一起交（分片是纵向的，每片写布局之前各出一次），不另设一道批准。

Figma 给的是 375 宽画板上的绝对坐标和宽高。把这些数字原样抄成「平铺的 View + 挂 parent 的 margin + 写死宽高」，结果就是散乱、不适配、每次调整都要动好几个 View。

## 0. 没有设计就不做，先拿参考图

- **这块 UI 没有 Figma node 也没有截图，就停下来要**，不先做一版等人改。有设计只缺切图是另一回事，见第 3 节。
- **动手前把目标 frame 整张导出 PNG 并看图**（参考图，放 `.figma-out/` 不入库）。有哪些可见元素、是平涂还是复杂图形，都以参考图为准；节点数据只取尺寸、间距和文案。只读节点数据会漏元素，还会用 fill 颜色仿造出一个简化的背景。
- 帧表里每个角色、每个状态都要有对应的参考图或截图。缺了就登记「缺状态帧」并问，不按相邻状态推测。

## 1. 分块：写 XML 之前先出分块表

满足任一条就是一个块，一个块一个容器：

- 一起移动（拖拽、整体位移动画）
- 一起显隐（同一个状态控制）
- 共用一张背景
- 作为整体居中或对齐（图标 + 文字整体在按钮里居中）

块内元素只约束到块内兄弟或块容器；块之间只在块容器这一层挂约束。Figma 的 frame / group 层级可以当初稿，但设计偷懒时 group 不一定按块分，以上面的判据为准。

「ConstraintLayout 扁平化」是列表项、深层级的性能建议。十几个 View 的面板嵌套两三层，成本可以忽略；为了扁平把块拆散，换来的是每次调整都要改一串 margin。

| 块 | 容器 | 包含元素 | 宽 / 高语义 | 和相邻块的关系 | 资产 |
|---|---|---|---|---|---|

表经用户确认后再写 XML，确认放在哪一步见开头的适用范围。

## 2. 尺寸语义：每个数字先问它是什么

宽和高各选一种：

| 语义 | 用在 | XML |
|---|---|---|
| 固定 | 图标、头像、切图固有尺寸、触控区 | `Ndp` |
| 跟内容 | 文字、文案可变的按钮、包住内容的块 | `wrap_content`，配 `maxLines` / `maxWidth` / `minHeight` |
| 填满 | 占满两侧约束之间 | `0dp` + 两侧约束 |
| 比例 | 按父宽等比、切图固定宽高比 | `0dp` + `layout_constraintDimensionRatio` / `layout_constraintWidth_percent` |

设计稿用了 auto layout 时按它的 sizing 翻译：Hug → 跟内容，Fill → 填满，Fixed → 再判断是真固定还是设计师随手定的。没用 auto layout 时按元素类型推断，不按数字。

- **父容器跟屏幕变，子元素就不能全部写死宽度。** 一行几个兄弟各写死宽度、加起来逼近父宽，窄屏必然挤出。改成 chain + `0dp`（按需配 `layout_constraintWidth_max`）。
- **装着可变文字的容器，高度不写死。** 背景切图不能拉伸时，去问设计能不能出 .9 图，不要用写死高度掩盖。
- **margin 取「和相邻元素的间距」，不取「到父容器顶或底的距离」。** 纵向位置挂在上一个元素下面，上面的元素一变，下面跟着走。
- **对齐关系用约束表达**：居中于某元素、底边对齐、居中于某元素下方，都用约束，不用 margin 凑。
- **例外**：悬浮层（可拖拽浮窗、盖在视频上的面板）本身没有相邻元素可挂，直接挂 parent 加 margin 是对的。

写完数一遍：每个写死的宽高和每个 ≥20dp 的 margin，都要说出属于上表哪种语义或哪条例外。说不出来就是抄了数字。

## 3. 资产清单

把设计稿或截图里每个可见元素编号，逐项填：

| 元素 / 帧 | 视觉证据 | 实现来源 | 切图已包含 | 缺什么 | 是否阻塞 |
|---|---|---|---|---|---|

- **视觉证据**指向具体 Figma node、标注截图或现有页面；「和某卡片差不多」不算。必须是本轮亲眼看过的图，用户提到但没给的，先要。
- **实现来源**只允许：完整切图 / 原生控件 / 文案 / 仅状态变化 / 复用仓内资源。文案注明来源是服务端字段还是本地 string，服务端字段先查它是否已包含设计稿上的全部文字，避免重复拼接。
- **原生绘制只用于参考图上确认是平涂的元素**（纯色或简单渐变 + 圆角）。有多层、阴影、纹理、装饰的，一律要切图。
- **切图已包含**：导出的节点图常常自带文字、边框、装饰。已包含的不再建 View 叠上去。节点里带动态内容（昵称、头像、倒计时）的不能整张当切图，要让设计拆。
- **有完整背景或组合切图时整体使用**，不拆成星星、光晕、爱心等装饰 View 重新拼。
- **缺切图不挡结构。** 容器、尺寸、约束照做；`src` / `background` 引用按用途命名的资源，先放不带任何图形的纯色占位，在表里登记「缺切图」，切图到位只替换同名文件，XML 不动。占位不仿造图形，交付时明说哪些是占位。截图能证明布局和状态，但不是可打包资产。
- **导出失败要报告，不自行替换。** SVG 导出为空时换 PNG @3x 再导一次；仍然失败就登记「缺切图」告诉用户，不用自己画的图形顶替。
- **缺口汇成一张单子一次性给用户或设计**，不要边写边问、一轮问一个。缺切图、缺状态帧、缺文案都进这张单子。
- **导出倍率对应密度目录**：1x → `drawable-mdpi`，2x → `drawable-xhdpi`，3x → `drawable-xxhdpi`。PNG 放进不带后缀的 `drawable/` 等于 1x，在 3 倍屏上放大三倍；写死宽高能遮住显示问题，遮不住内存浪费。

## 4. 按块交付

一个块写完就是一个检查点：拿这个块的渲染截图对照同一个 Figma node，过了再写下一块。多状态的块按「角色 × 状态」逐帧对，文案和显隐来自 `requirement-frames` 的帧表。

口头复述「我理解是××卡片」不能代替截图对照。自己无法渲染时，明确请用户截哪一块、哪个状态。

## 症状 → 排查

| 症状 | 原因 | 回到 |
|---|---|---|
| 用户反复说「对照设计图」 | 抄了截图的样子，没抄结构 | 分块表 |
| 用户要求「包一个容器方便调整」 | 漏了块 | 分块判据 |
| 长文案被截断或溢出 | 容器写死高度 | 尺寸语义 |
| 窄屏元素挤出或重叠 | 兄弟元素各写死宽度 | 尺寸语义 |
| 调一处 margin，另一处跟着错 | margin 挂在 parent 上，不是相邻元素 | 尺寸语义；链的行为见 `constraintlayout.md` |
| 图上同一段文字出现两层 | 切图已包含文字，又叠了 TextView | 资产清单「切图已包含」 |
| 做出来的元素设计稿里没有 | 没有设计就先做了，或缺切图时自创 | 第 0 节；资产清单登记缺口 |
| 少了背景、图标等元素，或背景被简化成纯色 | 只读了节点数据，没看参考图 | 第 0 节参考图 |
| 某个图标换成了设计稿里没有的样式 | 导出失败后自行替换 | 资产清单「导出失败」 |
| 图标在某些机型上特别大或特别糊 | PNG 放错密度目录 | 资产清单「导出倍率」 |
